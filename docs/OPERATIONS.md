# 操作方法

输入前读 INSTALL 与 BRIDGE；首次最小验收通过后才跑真实任务。任务目标、已领分项、当前位置和资源由当前画面核实。用户接管后停止，恢复时重新观察。

## 寻宝和导航

先明确地图版本、楼层、角色、朝向、目标入口与最近锚点。背包按名称选择寻宝道具，千星城普通箱案例使用感应力学探测棒，不能依赖背包上次选中。探测标记可能切换地图显示层，角色层与目标层分别读；普通箱探测不覆盖全部谜题和贼灵。

每次传送、转镜或变层，用短移和小地图背景核方向。相同缩放和移动模式下，以背景位移/按住时间估速度。沿通路折线估距离，用门框、墙角、楼梯与栏杆定地标；地图直线不等于可走距离。小地图角色居中时读背景反向位移。

确定直路合批，到拐角前留短移余量。焦点和回执正常却无位移时，检查碰撞、错层与断桥，只试能区分原因的动作。未知入口先查实景，按本轮目标取舍。收益按实收奖励与墙钟，不按输入数量。

## 多帧与批量

岔路、跨层或遮挡时，在同一观察批补足必要画面，通常 2–3 帧：已有地图/全景、入口侧角、必要的落点。两处固定地标交叉核位移，遮去 HUD、箭头和轨迹后才做图像配准。地图、朝向、缩放不一致就重新校准。第一张可操作画面是计时起点。

动作预案写目标、前置条件、坐标系、有序动作、持续时间、验收地标与停止条件。已知直路分成 ≤1000ms 指令，逐条 ACK 后继续，转角、变层、交互和收奖作为画面节点。可在战斗和加载期间准备下一批，实际输入前仍需核归属、前台和新画面。

## 交互与谜题

近 F 先读文案；多个提示滚轮选中。对话中 M 可能进入设置，先确认已回探索。地图第一次 Escape 可能只取消标记选中。菜单等待由实际加载决定，项目常见 0.9–1.1 秒不是保证。

谜题先对齐棋盘、阶段与机关状态。拖拽在注册允许时用按下、20 步插值、松开，阶段完等待角色走到齿轮再看图。黄金替罪羊、矩阵、迷钟、ROTATE/JUMP 与回溯各读技能对应参考。回执、机关生效、关卡完成、收尾对白与奖励入账分开记录。

## 工具与记录

`map_align.py` 对两张已保存的同层地图估部分仿射投影，依赖 OpenCV/NumPy；不足匹配返回非零，不以投影代替入口和楼层核验。`wait_foreground.py <本地PID>` 等前台事件而不主动抢焦点，事件只是唤醒条件，仍须 ready 和新画面。

本地进度记录地图/层、地标、朝向、实际完成分项、奖励及证据类型、输入状态、下次第一步。未知奖励保持未知；用户现场确认注明来源，余额推算与直接奖励弹条分别写。收尾恢复本任务临时更改的设置，原设置由本机记录，不能套用作者设备参数。
