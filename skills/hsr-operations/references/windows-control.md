# Windows 控制

按本机登记的 REPO_ROOT 读 `docs/INSTALL.md` 与 `docs/BRIDGE.md`。公开包只使用后期单槽 `keys|...` / `click|...` 协议；早期 Sequence sender 不属于本包依赖。

原生 CUA 窗口取图后正常查 ControlStatus，仅在 ready、游戏前台、用户交回控制和当前宿主允许此输入通道时执行。user 时立即让出，ai 时等待正常就绪，超时停止。桥无法代查宿主归属，不可脱离操作者守卫无人运行。只允许 CUA 的宿主遵守该限制。

坐标区分 screenshot、screen 与 client。窗口移动、DPI 或分辨率改变后重新校准。帮派迷钟的历史比例只适用于该次记录，不能当全局常数。

每条命令等新增 ACK，回执未知停余下指令，不能覆盖槽或重放整批。ACK 不能证明游戏动作或奖励成功。用户接管、失焦、窗口几何改变后丢弃旧计划，新画面再规划。

2026-11-21「欢闹厨房」首单实测。普通权限下 `SetCursorPos` 失败，`SendInput` 报已接收但实读的光标坐标未变。既有获准桥的单击能移动光标，先后点击盘子和顾客未触发交付。核对最新客户区坐标、ready、游戏前台、唯一操作者和空槽后，从宿主正常授权的管理员入口运行 `click-aware-game.ahk`，按住鼠标分 20 步从盘子拖到顾客，实见对话推进。按当前授权选择入口。等辅助进程退出后再恢复桥发送，交付以界面状态验收。

AHK 新脚本先普通权限 `/Validate /ErrorStdOut=UTF-8`，通过后才按正常授权现场验收。错误弹窗不点 Continue。控制桥遇状态文件短暂共享冲突会重试写入，持续冲突会退出。短读日志及时关句柄。公开 sender 读日志遇 Windows 错误 32 或 33 时，在原 ACK 截止时间内按原偏移继续读取，仍逐次检查控制归属和前台。ACK 缺失时重新取图核实实际位移，处理步骤见 `docs/BRIDGE.md`。

## 胶囊采样辅助与 stdout Error (6)

回溯辅助 `tools/rewind-cue.ahk` 接口、配置、预算与退出码见 BRIDGE。先实见针盘，在当前客户区校准独立胶囊中心，初始必须非青。总预算 12 秒，失焦或窗口几何变化即停，finally/退出回调释放 Space。edges 和退出码不能替代挑战成功及奖励画面。历史 stdout 错误修版改为先释放按键再写独立结果文件；公开版写本地运行目录。

原生 CUA 多帧和 Windows MCP 截图有不同控制开销，计时遵守 `docs/PERFORMANCE.md`，从第一张可操作帧至实际首派，菜单和走位分开。

## 连续观察与锁屏只读

普通走位需要连续看地标时，可用 OBS 窗口采集。单张核图、地图小字、奖励数字和精确点击优先用原生 CUA。OBS 画布有单独的缩放，点击前重新核客户区坐标。

需要在锁屏期间观察时，先在解锁状态为 OBS 新建场景集合，添加「窗口采集」，选中 `StarRail.exe`，将采集方法设为 Windows Graphics Capture（WGC）。只采游戏画面，关闭麦克风、桌面音频和应用音频。需要本地程序读取画面时，启动 OBS 虚拟摄像机，以 FFmpeg 的 `-f dshow -i "video=OBS Virtual Camera"` 读取，完成后关闭虚拟摄像机。[OBS 窗口采集](https://obsproject.com/kb/window-capture-sources)

在能运行 Node.js 并从 PATH 启动 FFmpeg 的本地宿主，可从完整仓库导入 `tools/obs_frames.mjs`。虚拟摄像机已输出游戏画面时，独立取一张图可在同一次调用中用 `openObsFrames()` 建立 reader，用 `await reader.nextFrame()` 取一张 960×540 JPEG，并在 `finally` 中调用 `reader.close()`。用宿主图像接口直接显示内存中的 `frame.bytes`。持续观察时保留同一个 reader，每次等下一帧，结束时关闭 reader，再停 OBS 虚拟摄像机。该 reader 只取图，派发仍走正常控制检查。

先看首帧能否认出游戏地标或界面，再核相邻帧的像素变化与可见动作。虚拟摄像机返回 OBS 占位图时，查看本次 OBS 启动日志，确认启动是否完成、`StarRail.exe` 的窗口采集是否使用 WGC，以及虚拟摄像机所选输出（如 Program 画面）是否包含该采集来源。恢复后重新取帧验收。超时或画面无法核实时，在解锁状态下用原生 CUA 重新取图。

用 `WTSQuerySessionInformationW` 的 `WTSSessionInfoEx` 会话标志确认锁屏及解锁。锁屏期间间隔取几帧，按上述步骤核实画面仍在更新。锁屏期间停发游戏键鼠。解锁后重新取图，确认游戏前台及控制归属，再按正常流程派发。[Windows 会话状态](https://learn.microsoft.com/en-us/windows/win32/api/wtsapi32/ns-wtsapi32-wtsinfoex_level1_w)

2026-11-19，Windows 上用 OBS 33.0.0 在龙骸古城 2F 瓦砾阶验证。约 86.5 秒锁屏期间以每秒 4 帧抽样，347 帧的像素哈希均不同，解锁后继续出图。同机普通权限的 OBS「游戏采集」报 `could not open process: StarRail.exe`，切到 WGC 窗口采集后成功。

### 持续按键时独立观察

需要连续按键并同步看机关时，用独立的只读进程预热 OBS 帧读取器。以本次操作的首个实时控制许可作为采样标记，让该进程定点取帧，按键结束后统一读取图和实际收帧时间。按键宿主专注实时控制状态与同代心跳续期。保持唯一操作者、游戏前台、会话解锁、同一操作持有独占输入且命令槽无待处理命令，失去许可或心跳超时立即松键，保留独立总时限与退出释放。

2026-11-21 眠宫迷津卷一，使用本地带超时释放的一次性长按辅助。按键宿主同时逐张调用终端截图时，一次续期耗时 753 毫秒，超过本次 750 毫秒看门狗阈值，辅助自动松键。改为独立 OBS 读图进程后，从首个许可自主取六帧，按键宿主的续期最长 64 毫秒，持续按键 18 秒。这些时长只描述本机实测。机关进展和实收以游戏画面核验。
